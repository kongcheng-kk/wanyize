18-3 SVG 架构图 · 基于知识库的智能客服系统

高级网页设计 I · 第 18 章 Canvas 与 SVG 图形 —— 一张可交互的科研级系统框架图

研究背景：为什么客服系统要「知识库 + 大模型」

传统规则式客服只能匹配关键词，换个问法就答不上；纯大模型客服又会一本正经地编造政策与价格。主流做法是 RAG（检索增强生成）：先把企业知识库做成分块向量索引，用户提问时先检索出最相关的若干知识片段，再交给大模型基于这些证据作答，并标注引用、无依据则拒答。下图把这套系统拆成七层 26 个模块，橙色「研」标记的是适合作为研究切入点的环节。

模块

01一条问句的完整旅程（11 步 + 闭环）
与图上「播放问答链路」的高亮顺序一一对应，从用户敲下回车到答案回到屏幕。
01

用户提问

网页客服窗、微信小程序、电话 ASR 转写、App SDK 四个入口，统一成文本 + 会话 ID。

02

接入网关

鉴权、限流、建立 WebSocket 长连接；按租户与渠道路由，QPS 超限直接排队。

03

意图识别

判断是「查订单 / 退换货 / 产品咨询 / 投诉」，决定走知识问答、业务查询还是转人工。

04

查询改写

结合对话历史补全指代（「它」→「X100 耳机」），做同义扩展与 HyDE 假设答案。

05

向量化

用 Embedding 模型把问句编码成 768 / 1024 维向量，供向量库做近邻检索。

06

混合检索

BM25 关键词召回 + ANN 向量召回双路并行，用 RRF 融合排序，兼顾术语精确与语义相近。

07

重排 Rerank

Cross-Encoder 对 Top-50 候选逐条打分精排，取 Top-5，显著提升上下文纯度。

08

上下文拼接

Top-K 片段去重、截断到模型窗口内，附上来源编号，供答案标注引用。

09

Prompt 组装

系统指令 + 会话历史 + 检索证据 + 输出格式约束（JSON / 引用编号 / 拒答话术）。

10

大模型生成

流式输出首字更快；约束「只用证据作答」，证据不足时输出「暂未查到」。

11

后处理与回环

敏感词过滤、置信度低于阈值转人工、附引用链接；答复回到用户，日志进运营闭环。

03三层评测指标
检索层看「找没找对」，生成层看「说得对不对」，业务层看「用户满不满意」。
层次指标含义
检索层Recall@K前 K 个片段里是否包含正确证据，衡量召回是否够
检索层MRR / nDCG@K正确证据排得靠不靠前，衡量排序质量
生成层Faithfulness答案的每个论断是否都能在检索证据里找到依据
生成层幻觉率无依据陈述占比，通常靠人工或强模型评审统计
生成层引用准确率标注的来源链接是否真的支撑该句答案
业务层首响时延 P95从用户发送到首字返回，流式输出能把体感压到 1s 内
业务层自助解决率未转人工且用户未追问即结束的会话占比
业务层转人工率 / CSAT转人工比例越低越好；CSAT 是会话结束后的满意度评分
04为什么架构图用 SVG 画
上面那张图是纯手写 SVG，不是截图也不是 Canvas。它和 18-2 的 Canvas 图正好可以对照着看。

01矢量：放大不糊

SVG 存的是坐标与形状，投影到 4K 屏、打印成 A4、插进论文 PDF 都是同一份清晰度；Canvas 存的是像素，放大就糊。

02文本可选可检索

图里的文字是真文字，可以选中复制、被搜索引擎索引、被读屏软件朗读，这对无障碍与文档检索很关键。

03可版本管理

SVG 是文本，git diff 能看出「改了哪个模块的名字」，论文投稿时还能用 Illustrator / Inkscape 再编辑。

04能像 DOM 一样被控制

内联 SVG 的每个 <g> 都是节点，可以 CSS 悬停、JS 点击、批量高亮——本页的交互就是这么做的。

<!-- 一张能交互的架构图，最小骨架大概是这样 -->
<svg viewBox="0 0 1240 780" role="img" aria-label="智能客服系统架构图">
  <defs>
    <!-- 箭头：refX 对准箭头尖，否则线会穿过箭头 -->
    <marker id="wan_arw" viewBox="0 0 10 10" refX="9" refY="5"
            markerWidth="6" markerHeight="6" orient="auto">
      <path d="M0 0 L10 5 L0 10 Z" fill="#93a5c4"/>
    </marker>
  </defs>

  <!-- 一个模块 = 一个 g，data-key 给 JS 用 -->
  <g class="wan_node" data-key="hybrid">
    <rect x="654" y="220" width="220" height="58" rx="10"/>
    <text x="764" y="244">混合检索</text>
  </g>

  <!-- 连线：marker-end 挂箭头 -->
  <path class="wan_edge" d="M764 142 V 152" marker-end="url(#wan_arw)"/>
</svg>
五个容易踩的细节

01viewBox 才是坐标系

width/height 只决定显示多大，viewBox 决定内部坐标范围。先定 viewBox（如 1240×780）再摆元素，才能等比缩放不变形。

02箭头不对齐 = refX 没调

marker 默认以起点为原点，箭头尖会「缩」在路径终点前或穿出去。把 refX 设为 9（10 宽箭头的尖端），端点才刚好贴住。

03text 不会自动换行

SVG 的 <text> 没有自动折行，长文本要手动拆成 <tspan x="…" dy="…">，所以架构图里每个模块只放标题 + 一行副标题。

04外链 SVG 控制不了

<img src="x.svg"> 是图片，CSS 和 JS 都进不去。要做悬停、点击高亮，必须把 SVG 内联写在 HTML 里。

05字体要显式声明

内联 SVG 会继承页面字体；但如果把图单独导出成 .svg 文件交给别人，要在 <style> 里写死 font-family，否则字体全变默认宋体。

✓和 Canvas 怎么选

元素固定、要可选中可交互 → SVG（架构图、流程图、图标）；成千上万元素、逐帧像素动画 → Canvas（18-1 的粒子、18-2 的流动数据包）。

本图共 7 层 26 个模块、29 条连线，全部由手写 SVG 构成，没有引用任何图片文件；点击任一模块可看它的职责与常见技术选型，橙色「研」标记对应上面六个科研方向。
