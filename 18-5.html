18-5 ECharts 关系图 · 画在笛卡尔坐标系上

高级网页设计 I · 第 18 章 图形与可视化 —— 把「关系」钉在坐标轴上，而不是让力导向随意摆

关系图不一定靠算法排版

ECharts 的 graph 系列默认用力导向布局：节点互相排斥、连线像弹簧，位置由算法算出来，适合展示「谁和谁有关系」。但只要加上 layout: 'none' 和 coordinateSystem: 'cartesian2d'，节点就会老老实实落在 x 轴类别 + y 轴数值交叉的位置上——既能表达关系，又能精确读出数值。这一页就是官方 graph-grid 示例的离线版。

图一周七天的关系链
7 个节点串成一条链：周一到周日。x 轴是类别（故意含一个超长标签），y 轴是数值，箭头表示相邻两天的流向。点「重新生成数据」换一组随机值。
layout: 'none' · coordinateSystem: 'cartesian2d'
01三个关键配置
普通关系图变成「坐标轴关系图」，只需要这三行。

layout: 'none'

关掉自动排版。默认值是 'force'（力导向），节点会自己漂移；设成 'none' 后位置完全由你给的数据决定。

coordinateSystem

'cartesian2d' 表示挂到直角坐标系：第 0 个数对齐 x 轴第 0 个类目，第 1 个数是 y 轴的数值。

edgeSymbol

['circle', 'arrow']：边的起点画小圆点、终点画箭头。edgeSymbolSize: [4, 10] 控制大小。

02数据与连线：全靠下标
节点是一个纯数字数组，第 i 个数就站在 x 轴第 i 个类目上；连线用 source / target 指向「第几个节点」。
/* 节点：下标即类别位置，值即 y 轴高度 */
var wan_axis = ['Mon', 'Tue', 'Wed', 'Very Loooong Thu', 'Fri', 'Sat', 'Sun'];
var wan_data = [123, 456, 789, 1011, 1213, 1415, 1617];

/* 连线：把相邻两天连起来（0→1、1→2 …） */
var wan_links = wan_data.map(function (item, i) {
  return { source: i, target: i + 1 };
});
wan_links.pop();   // 最后一个 6→7 没有第 7 个节点，必须删掉，否则报错

series: [{
  type: 'graph',
  layout: 'none',
  coordinateSystem: 'cartesian2d',
  data: wan_data,
  links: wan_links,
  symbolSize: 40,
  label: { show: true, formatter: function (p) { return p.value[1]; } }
}]
两个容易忽略的点：① links 里的下标越界不会画出来，但会在控制台报错；② 节点默认标签是「类目名」，长标签（如 Very Loooong Thu）塞进 40px 的圆会被裁成几个字母，所以这里用 formatter 改成显示数值，日期交给 x 轴。
03类目轴与数值轴分工
一个负责「是谁」，一个负责「多少」，混用就会画歪。
坐标轴类型作用
xAxiscategory类目轴，data 给出 7 个日期；节点按数组下标落位，不是按数值
yAxisvalue数值轴，节点值决定高度；轴刻度自动生成
boundaryGapfalse让首尾节点贴住绘图区左右边界，不被「半个刻度」的留白挤到中间
symbolSize40节点圆直径（px）；标签、箭头大小都跟着它调
04五个细节

01忘了 pop() 就报错

7 个节点只能有 6 条相邻连线，map 会多生成一条 6→7。links.pop() 就是删掉这条指向不存在节点的边。

02节点贴着 x 轴

数值小的节点会压住类目名。把 xAxis.axisLabel.margin 调大、grid.bottom 加高，标签就挪到下面去了。

03类目名太长

示例故意放了 Very Loooong Thu：类目轴会自动换行或旋转，节点标签却会被圆裁切。长文本一律改用数值或缩写。

04随机数据每次刷新都变

Math.random() 在页面加载时执行一次，所以每次刷新图形都不同。要固定效果就把数据写死或用固定种子。

05第二次 setOption 只传变化部分

换数据时只传 series: [{ data, links }] 就能保留坐标轴与样式；如果整个 option 重传又不加 true，旧配置会叠加。

✓什么时候该用它

既想看「关系」又想读数：任务流、状态机、日程链。纯关系网络（社交图、知识图谱）还是力导向更直观。
