JavaScript 的两种定时器 17-5

setTimeout 延时执行一次，setInterval 每隔一段时间重复执行。 两者都返回一个数字 id，分别用 clearTimeout / clearInterval 取消。 本页用四个可交互的演示把它们讲清楚。

01

先看一句话区别

两种定时器都属于浏览器的 宏任务，都不会阻塞后面的代码。区别只有一个： 回调执行完之后，还等不等下一次。

setTimeout 延时执行一次

等 N 毫秒后执行回调，执行完就结束，不会再来第二次。

返回值：定时器 id 取消：clearTimeout 常用：防抖、延迟提示、轮询
setInterval 每隔一段时间重复

每隔 N 毫秒执行一次回调，除非被清除，否则永远不会停。

返回值：定时器 id 取消：clearInterval 常用：秒表、轮播、倒计时
API 作用 参数说明
setTimeout(fn, delay, ...args) 等待 delay 毫秒后执行 fn 一次 fn：要执行的回调；delay：毫秒（省略为 0）；args：原样传给 fn
clearTimeout(id) 取消还没执行的 setTimeout id 为 setTimeout 的返回值；已执行过则无效果
setInterval(fn, delay, ...args) 每隔 delay 毫秒执行 fn 一次，直到取消 参数同上；delay 最小按 4ms 计算
clearInterval(id) 停止 setInterval 不停止会一直占用主线程，页面越跑越卡

      04
      
    演示三：0 毫秒的 setTimeout 也不是立刻执行
    
    
    
    
    
      这是面试常考、也是新手最容易踩的坑。setTimeout(fn, 0) 的意思是
      「尽快排进宏任务队列」，而不是马上执行。所以它的回调一定排在当前同步代码
      和所有微任务之后。
    
    

    
    
      1console.log('脚本开始');
      2setTimeout(() => console.log('定时器'), 0);   // 宏任务
      3Promise.resolve().then(() => console.log('Promise'));  // 微任务
      4console.log('脚本结束');
    
    

    
    
      
      
    
    

    
    
      实际执行顺序：
      ① 同步代码
      →
      ② 微任务
      →
      ③ 宏任务
    
    

    
    
      
    点「运行这段代码」，看看输出顺序。
    
    
    

    
    
      为什么？同步代码是「主线」，先把主线跑完；跑完后浏览器清空微任务队列（Promise.then）；
      微任务清空了，才从宏任务队列里取下一个（setTimeout 的回调）。所以即便延时写成 0，
      定时器也永远排在最后。

setInterval(function () { wan_fetchData(); }, 500);

// 推荐：本次任务结束后，再排下一次
function wan_loop() {
  wan_fetchData().finally(function () {
    wan_timer = setTimeout(wan_loop, 500);
  });
}
    
  
    

  
  
    
    
    
      06
      
    六个必须知道的细节
    
    
    

    
      
      
    1. 单位是毫秒。写成 setTimeout(fn, 3) 是 3 毫秒，不是 3 秒；要 3 秒得写 3000。
      2. 
      
    2. 定时器不精确。主线程被长任务占用时，回调只能排队等着，实际时间会晚于设定值。
      3. 
      
    3. 浏览器会节流后台标签页，最小间隔可能被拉到 1000ms 甚至更低频率，所以别用它做精确计时。
      4. 
      
    4. 第一个参数请传函数，不要传字符串 "alert(1)" —— 那会被当作代码执行，既不安全也查不出错。
      5. 
      
    5. 回调里的 this 默认指向 window（严格模式下是 undefined），需要时用箭头函数或 bind。
      6. 
      
    6. 页面切换 / 组件销毁前一定要 clear，否则定时器会在后台一直跑，造成内存泄漏。
      7. 
    
    

    
    // 一个好习惯：把定时器统一登记，离开页面时一次性清干净
var wan_timers = [];

wan_timers.push(setTimeout(wan_tip, 3000));
wan_timers.push(setInterval(wan_tick, 1000));

window.addEventListener('beforeunload', function () {
  wan_timers.forEach(function (id) {
    clearTimeout(id);   // 同一套 id 池，两种都能清
    clearInterval(id);
  });
});
